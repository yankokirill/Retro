## Подозрения (без воспроизведения)

- **CLAUDE.md § 4** приводит мутационное тестирование `packages/crdt` (Stryker, порог ≥ 80%, `npm run check:mutation`) как один из способов доказательства качества тестов. В репозитории нет ни Stryker-конфигурации, ни скрипта `check:mutation` ни в корневом `package.json`, ни в `packages/crdt/package.json`. Не включаю в «Расхождения», так как раздел 8 того же файла (план по вехам) явно относит мутационное тестирование к «Этап 5» (недели 10–13), который по датам ещё не наступил — вероятно, добросовестный разрыв между «целевым» описанием раздела 4 и текущим состоянием, а не потерянная работа.
- Аналогично не включены в «Расхождения» отсутствующие `check:perms`, `check:security`, `check:nojs`, `test:e2e`, `tools/check-perms`, `tools/retro-mcp`, `e2e/` — все они относятся к вехам В4/В5, которые по чеклисту `CLAUDE.md` § 8 отмечены как ещё не пройденные (пункты без `[x]`), и `npm run check` в `package.json` их сознательно не вызывает.

## Проблемы спецификации

- `docs/security/permissions.md` сама честно документирует пробел из находки 1 в разделе «Сознательно не в T-011» (создание/переименование группы, assignee/done/удаление action item — «не потому что всем можно, а потому что ни одна задача ещё не назначена»). Формально это делает находку 1 «известным долгом», а не скрытым багом — но ни `requirements.md` (REQ-012, REQ-018, REQ-019), ни `CLAUDE.md` § 5 не содержат явной оговорки «до T-016/T-019 эти действия доступны всем ролям без проверки»: читатель одной только `requirements.md` (первый по приоритету источник) сделает вывод, что критерии REQ-012 уже выполняются с проверкой прав. Стоит явно пометить эти REQ как «не покрыты правами до T-016/T-019» либо в самой `requirements.md`, либо явной перекрёстной ссылкой.
- `docs/spec/consistency-model.md` § 13 использует совершенный вид прошедшего времени («получил», «решено») для записи решения ADR, принятого в тот же день без изменения кода (см. находку 2). Для документа-источника истины это создаёт двусмысленность между «согласовано» и «реализовано»; `docs/tasks.md` этой проблемы не имеет (там корректно «получает» в рамках будущей T-014).
