# ADR-0004: Одновременные правки текста — оба видимых варианта (MV-регистр), не автослияние

- **Статус:** принято
- **Дата:** 2026-09-13

## Контекст

Два участника одновременно меняют текст одного стикера. Нужна детерминированная политика: что видят все после синхронизации. `docs/brief.md` явно исключает посимвольное слияние (RGA/OT) как задачу MVP.

## Решение

Поле `text` (и `title` группы) — multi-value регистр: видимая запись перекрывает только те записи, которые её автор **видел** в момент правки (§ 1.4, § 2 `docs/spec/consistency-model.md`). Одновременные, не видевшие друг друга правки остаются видимы **обе** — REQ-007 явно требует показать конфликт, а не выбрать победителя молча.

## Рассмотренные варианты

- **MV-регистр, оба варианта видны (выбран)** — ни одна правка не теряется молча (REQ-025, I2.2). Простая реализация: та же структура данных, что и у остальных полей (§ 2), отдельного примитива не нужно.
- **Last-writer-wins по метке** (как у `place`/`color`) — проще для UI (всегда одно значение), но участник тихо теряет свою правку без предупреждения. Прямо противоречит критерию REQ-007 («ни один не потерян») и общей проблеме из брифа («договорённости растворяются»).
- **Посимвольное слияние (RGA/подобное Automerge Text)** — решило бы конфликт автоматически и без потерь, но кратно увеличивает сложность модели и объём доказательств (нужны отдельные инварианты про порядок символов) ради поведения, которое пользователь ретро-доски не ожидает от короткого текста на стикере. Явно исключено в `docs/brief.md`.

## Последствия

- Интерфейс обязан уметь показать «конфликт» как первоклассное состояние стикера (REQ-007, кр. 1), а не только «текст».
- Разрешение конфликта — обычная новая правка текста (REQ-007, кр. 2): значит, participant с правом редактировать стикер способен неявно «принять» чужой вариант, просто сохранив его как новый текст — отдельного UI-действия «выбрать чей текст победил» не требуется.
- Если позже понадобится посимвольное слияние (бонус, `docs/brief.md`) — это отдельный ADR и отдельный тип поля, MV-регистр для `text` не выбрасывается, а становится fallback-поведением при отсутствии совместного редактирования в реальном времени.
